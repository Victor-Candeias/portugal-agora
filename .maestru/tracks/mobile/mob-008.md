# MOB-008: Mobile: atualizar rotas da API Aberta (Tempo, EV, Economia, risco de incêndio)

## Contexto

Com uma chave válida, `ApiAbertaClient` (`packages/core/src/api/client.ts`) recebe **404** em quase todas as rotas: a API Aberta mudou os prefixos. Sem chave a resposta era 401, o que escondia o problema. Teste feito a 2026-10-09; as rotas atuais estão na especificação OpenAPI em `https://api.apiaberta.pt/docs/json`.

| Rota usada hoje | Estado | Rota atual (candidata) |
|---|---|---|
| `/weather/forecast` | 404 | `/ipma/forecasts/{cityId}` (lista em `/ipma/forecasts`, locais em `/ipma/locations`) |
| `/weather/observations` | 404 | — (não encontrada) |
| `/civil-protection/alerts` | 404 | `/ipma/warnings` (avisos meteorológicos) |
| `/civil-protection/fire-risk` | 404 | — (sem rota; alternativas: RCM do IPMA em open-data ou focos `/nasafirms/hotspots`) |
| `/ev/stations` | 404 | — (prefixo `/ev/*` existe, sub-rota por descobrir) |
| `/statistics/indicators` | 404 | `/ine/indicators` |
| `/finance/rates` | 404 | `/bdp/rates` |
| `/fuel/*`, `/geo/*`, `/anpc/*` | 200 | sem alterações |

Ecrãs mobile afetados (sem dados com ou sem chave):
- tabs Tempo, EV e Economia (`apps/mobile/app/(tabs)/`, via `hooks/useApi.ts`);
- cartões Tempo e Euribor do Início;
- cartão "Risco de incêndio" da Proteção Civil (`hooks/useAnpc.ts` → `useFireRisk`).

No web, as páginas não usam estas rotas: Tempo usa Open-Meteo, o Início usa IPMA, e EV e Economia são `ComingSoon`. Os hooks antigos do web (`useAlerts`, `useEconomy`, `useEV`, `useWeather`) não são usados.

## Objetivo

- Atualizar `ApiAbertaClient` e os tipos para as rotas atuais e adaptar o formato das respostas (ex.: `/bdp/rates` devolve `key`/`label`, `/ipma/forecasts/{id}` devolve `tMin`/`tMax`).
- Onde não há rota equivalente, usar a mesma fonte do web (ex.: Open-Meteo para o Tempo) ou outra fonte pública:
  - risco de incêndio → RCM do IPMA ou focos NASA FIRMS;
  - EV → confirmar o que existe em `/ev/*`.
- Remover do core e do web os métodos e hooks que deixarem de ter uso.
- Validar com um smoke test contra a API real (com `EXPO_PUBLIC_APIABERTA_KEY`) e com typecheck, lint e `expo export -p android`.
- Atualizar o README: variáveis `.env` por app (`apps/mobile/.env` → `EXPO_PUBLIC_APIABERTA_KEY`, `apps/web/.env` → `VITE_APIABERTA_KEY`) e rotas usadas.

## Notas

- `.env.example` na raiz tem o que parece ser uma chave real commitada. Substituir por um valor de exemplo (a revogação da chave fica com o dono).

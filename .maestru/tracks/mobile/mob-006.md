# MOB-006: Android Auto: corrigir manifest, HostValidator, signing e targetSdk

## Contexto

AA-001 está `done`, mas `apps/android-auto`:
- `AndroidManifest.xml` não declara `PortugalHojeCarAppService` (intent-filter `androidx.car.app.CarAppService` + categoria) nem o meta-data `com.google.android.gms.car.application` → a app não aparece no Android Auto.
- `PortugalHojeCarAppService` usa `HostValidator.ALLOW_ALL_HOSTS_VALIDATOR`.
- Release assinado com a debug keystore; `isMinifyEnabled = false`.
- `targetSdk`/`compileSdk` 34 — abaixo do exigido pelo Google Play para novas apps.
- Chave lida de `VITE_APIABERTA_KEY` (nome herdado do web).

## Objetivo

- Declarar o serviço e o meta-data no manifest; validar no Desktop Head Unit (DHU).
- HostValidator restrito em release (allowlist de hosts), `ALLOW_ALL` só em debug.
- Signing de release via keystore externa/variáveis de ambiente; minify + regras ProGuard.
- Subir compileSdk/targetSdk para o mínimo exigido pelo Play.
- Avaliar elegibilidade das secções face às categorias permitidas no Android Auto (POI, meteorologia…) e decidir se a app se funde com `pt.portugalhoje.app`.

## Progresso (2026-10-08)

Implementado (ver `mob-006-spec`): serviço + categoria POI + meta-data no manifest; HostValidator restrito em release; compileSdk/targetSdk 36; signing por variáveis de ambiente; R8/minify + keep rules Gson; `APIABERTA_KEY`; README atualizado. `assembleDebug` e `assembleRelease` compilam.

**Pendente para fechar:**
- Validar no DHU/carro (requer dispositivo).
- Decisão do owner sobre as secções não-POI (Tempo, Proteção Civil, Transportes CP) e fusão com `pt.portugalhoje.app`.

# WEB-042: Concelhos (web e mobile): ficha do concelho via API Aberta /geo

## Contexto

O `ApiAbertaClient` do core já tinha `getDistricts()` e `getMunicipalities()` (`/geo/*`), mas nenhuma app os usava. Os seletores de distrito e concelho vêm da DGEG, porque a pesquisa de postos precisa dos IDs da DGEG. A análise de 2026-10-11 deu o seguinte:

- `/geo/municipalities?limit=400`: os 308 concelhos, com código INE, distrito, coordenadas e área. Quase todos têm email (303), telefone (304) e código postal (304); `website` vem sempre `null`. Por omissão a API devolve 50 por página. Cerca de 100 KB, ~170 ms.
- `/geo/municipalities/{slug}`: o mesmo concelho mais `geojson` (Feature Polygon/MultiPolygon com a fronteira), cerca de 30 KB.
- `/geo/parishes` não liga as freguesias ao concelho nem ao distrito (fica de fora). Os distritos (`/geo/districts/{código}`) pesam ~500 KB com a fronteira (fica de fora).
- O CORS permite o browser (preflight `x-api-key` OK), por isso o web chama a API diretamente.

## Objetivo

Nova secção **Concelhos** no web e no mobile:

- Lista dos 308 concelhos, com pesquisa sem acentos e filtro por distrito.
- Ficha do concelho: distrito, código INE, área, contactos da câmara (telefone, email, código postal) e fronteira no mapa.
- A lista quase não muda, por isso fica em cache persistente durante 30 dias: `localStorage` no web e `expo-sqlite/kv-store` no mobile. Se a API falhar, usa a cache expirada.
- Não substituir a DGEG no ecrã de Combustível.

# WEB-068: Tráfego aéreo: Fase 0 — validação das fontes ADS-B (termos, quotas, cobertura) e escolha do proxy

## Contexto

Origem: `Documents/implementacao_trafego_aereo_web_mobile.md`. O guia propõe ASP.NET Core, Kotlin/Compose e MongoDB. O projeto real é diferente:

- web estática no GitHub Pages;
- mobile em Expo 57 / React Native com MapLibre;
- lógica partilhada em `packages/core`;
- sem backend.

O guia vale pelo contrato REST (§4), pelos campos normalizados (§2.3) e pelas regras de integração (§5.4). A pilha tecnológica que propõe não se aplica.

## Testes preliminares (23/10/2026)

| Fonte | Resultado | CORS no browser |
|---|---|---|
| adsb.lol (`/v2/lat/38.72/lon/-9.14/dist/200`) | 200, cerca de 60 KB. `x-ratelimit-limit: 4/s, 60/min, 500/dia` por IP | ❌ sem `Access-Control-Allow-Origin` |
| OpenSky (`/api/states/all` com bbox) | 200, créditos anónimos limitados (397 restantes) | ❌ só `opensky-network.org` |
| Airplanes.live (`/v2/point/...`) | 403 | ❌ |

O que isto implica:

- **Web:** não pode chamar as fontes diretamente. Também não pode publicar snapshots no Pages, porque o cron é de hora a hora e a funcionalidade precisa de dados de cerca de 60 s. É preciso um proxy com cache.
- **Mobile:** sem CORS, mas 500 pedidos/dia por IP chegam para só cerca de 8 h de atualização a cada 60 s. Também deve usar o proxy.

## Objetivo

1. Confirmar os termos de uso, a licença (ODbL), a atribuição e a redistribuição da adsb.lol, através de um proxy público. Fazer o mesmo para o OpenSky como alternativa.
2. Mapear os campos brutos da adsb.lol para os campos normalizados do guia (§2.3). Confirmar as unidades:
   - `alt_baro` / `alt_geom` em pés;
   - `gs` em nós;
   - `geom_rate` / `baro_rate` em ft/min;
   - `seen` / `seen_pos` em segundos;
   - `alt_baro` com o valor `"ground"`.
3. Definir as regiões e os centros (continente norte/sul, Açores em vários grupos, Madeira) e o raio de cada um. Medir a sobreposição e o custo em quota.
4. **Decidir onde corre o proxy:** Cloudflare Worker (gratuito, com cache no edge), o servidor Docker local (WSL, porta 10000) ou outro. Registar a decisão neste work-item.
5. Definir o intervalo de atualização e o TTL da cache, compatíveis com as quotas.

## Critérios de aceitação

- Termos, licença e atribuição documentados aqui, com ligações.
- Mapeamento de campos e unidades validado com respostas reais.
- Regiões e centros definidos, com o número de pedidos por ciclo.
- Decisão sobre o proxy registada. Desbloqueia o WEB-069, o WEB-070, o WEB-071 e o MOB-022.

**Fora de âmbito:** implementação.

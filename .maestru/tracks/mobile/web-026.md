# WEB-026: Proteção Civil: comunicados da ANPC via API Aberta (/anpc/warnings)

## Contexto

`GET /v1/anpc/warnings` devolve os comunicados da ANPC/ANEPC (via fogos.pt), paginados (`meta` + `data`, com `id` e `text`). Exemplo: proibição de queimas e queimadas. No teste de 2026-10-09 havia 39 comunicados. A app só usa `/anpc/incidents` e `/anpc/summary` (`packages/core/src/api/anpc.ts`).

## Objetivo

- Adicionar `getWarnings()` ao cliente ANPC no core.
- Mostrar os comunicados mais recentes no ecrã Proteção Civil (web `ProtecaoCivil.tsx`, mobile `protecao-civil.tsx`).
- Avaliar também `/anpc/incidents/active`, que já devolve só as ocorrências ativas e evita filtrar no cliente.

## Notas

- `/anpc/risk` veio vazio (`count: 0`) no teste. Manter o RCM do IPMA para o risco de incêndio.

## Implementação

Ver `web-026-spec`.

- **Core:** `anpcClient.getWarnings()` lê todas as páginas de `/anpc/warnings` (`limit=200`, o máximo aceite) e ordena do mais recente para o mais antigo pela data do `label`, porque a API devolve os mais antigos primeiro. `formatAnpcWarningDate` formata a data. Também foi acrescentado `getActiveIncidents()` (`/anpc/incidents/active`).
- **Web e mobile:** o ecrã Proteção Civil tem o cartão "Comunicados da Proteção Civil" com os 5 mais recentes e "Ver mais". O botão de atualizar também recarrega os comunicados.
- **`/anpc/incidents/active`:** devolve as mesmas ocorrências que `/anpc/incidents`, incluindo as "Conclusão" (com `active: true`), por isso não evita o filtro no cliente. Só o `count` difere (`/incidents` devolveu 1 para 5 ocorrências). As apps continuam a usar `/anpc/incidents`.

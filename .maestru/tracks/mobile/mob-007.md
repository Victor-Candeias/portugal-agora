# MOB-007: Mobile: CI de build Android + publicação em teste interno no Google Play

## Contexto

O único workflow (`.github/workflows/deploy.yml`) faz deploy do web para GitHub Pages. Não há pipeline de build Android nem conta/listagem no Google Play.

## Objetivo

- Workflow GitHub Actions para build AAB (EAS Build ou Gradle após `expo prebuild`), com secrets para keystore e API keys.
- Se for usado EAS Build: `npx eas-cli login` + `npx eas-cli init` em `apps/mobile` (requer conta Expo) para gravar `extra.eas.projectId` no `app.json` (passado do MOB-001, que ficou só com builds locais).
- Conta Google Play Console, Play App Signing, listagem (ícones, screenshots, feature graphic).
- Política de privacidade (uso de localização), formulário Data Safety, classificação de conteúdo.
- Publicação em teste interno/fechado (contas pessoais novas: 12 testers durante 14 dias antes de produção).
- Avaliar exposição da chave API Aberta embutida no APK (limites/rotação ou proxy próprio).

## Depende de

MOB-001.

## Progresso (2026-10-09)

Implementado (ver `mob-007-spec`): workflow `.github/workflows/android.yml` (`expo prebuild` + Gradle, sem EAS — o `eas init` deixa de ser necessário), AAB + APK como artefactos e publicação opcional numa faixa do Google Play; config plugin `withReleaseSigning` (assinatura e `versionCode` por variáveis de ambiente); política de privacidade em `apps/web/public/privacidade.html`; respostas propostas de Data Safety/classificação e decisão sobre a chave API Aberta na spec.

**Pendente (manual, requer contas do owner):** conta e app na Play Console, upload keystore + secrets do repositório, primeiro upload manual, listagem (ícones/screenshots/feature graphic), formulários e teste fechado (12 testers × 14 dias).

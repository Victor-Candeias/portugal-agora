# WEB-051: Energia: Fase 0 — prova de dados ENTSO-E (token, A75/A65, EIC de Portugal, latência)

## Contexto

Segundo o relatório `Documents/relatorio_energia_portugal.md`, a ENTSO-E Transparency Platform é a alternativa para séries intradiárias de produção real por tecnologia e carga real. A API (`https://web-api.tp.entsoe.eu/api`) exige registo e `securityToken`, e devolve XML.

Consultas relevantes (parâmetros por confirmar):

- **Actual Generation per Production Type**: `documentType=A75` (`processType` a validar).
- **Actual Total Load**: `documentType=A65`.
- **Cross-border physical flows**: `documentType` próprio, a confirmar.
- Código EIC da área de Portugal: confirmar no catálogo oficial, não fixar sem validação.

## Objetivo

Prova de dados (Fase 0 do relatório), sem código de produção:

- Registar a conta e pedir o token da API (ação do utilizador). O token nunca entra no repositório, no bundle nem em JSON público.
- Confirmar o código EIC de Portugal e os parâmetros de A75, A65 e fluxos transfronteiriços.
- Documentar a estrutura XML: `TimeSeries`, `Period`, `resolution` (PT15M/PT30M/PT60M), `Point`, códigos de tecnologia (PSR), unidades, revisões e erros estruturados.
- Medir a latência real de publicação e propor o `max_age_minutes` da fonte.
- Confirmar as condições de utilização e de republicação dos dados.
- Decidir a fonte canónica do indicador intradiário (REN ou ENTSO-E), com base também no WEB-050.

## Resultado esperado

Spec `research-v1` com respostas reais (sem o token), o mapeamento provisório dos códigos PSR e a decisão.

## Notas

- **Adiado** (decisão de 2026-10-19): o âmbito inicial é só o painel diário (WEB-050 a WEB-056), só com a REN.
- **Resolvido (2026-10-19):** o utilizador obteve o token (`TRANSPARENCT_ENTSOE_TOKEN`). Resultados e decisão em `web-051-spec`.
- Se o token não for obtido, o MVP diário (WEB-053, WEB-056) avança só com a REN e o intradiário (WEB-057, WEB-058) fica bloqueado.
